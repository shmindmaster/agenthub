Choose the account/profile for this task. Run `node scripts/start-session.mjs` relative to this skill directory. It selects the configured automation profile (Edge Automation by default) explicitly and starts an Agent Window with `--no-focus`. If the profile is missing or ambiguous, stop and report it. Never fall back to the only connected personal browser. Use this launcher for CLI, capture, recipe and verification tasks. Do not start through raw MCP, `bsk open`, an implicit session, or a direct `bsk session start`.

Keep the returned session ID on every command. Give each concurrent task its own session and tabs. Sessions in one profile share website sign-in state. For different accounts on the same site, use different approved profiles or isolated browser contexts. End only your session, including on failure. Never use a global session stop or restart a shared daemon as task cleanup.

## Reproducible operator walkthroughs

When the deliverable teaches a person to complete a workflow, begin at the application's normal entry point and the selected role's real post-login home. Teach the route a user can follow from that home. Do not use a deep link, URL edit, hidden route, direct API call, script, or browser shortcut to skip a step in the teaching sequence. A base URL for opening the application is fine. If setup or authentication cannot be performed through the visible route, record that as setup outside the walkthrough and start the captured sequence at the role's home.

Enact and show each user-visible step in order: open menus, choose options, scroll to controls, enter or select values, and invoke actions. Do not imply a step occurred from narration, a jump cut, or a final screen. Re-observe after navigation or layout changes, and keep the whole application viewport visible so the user can orient themselves. For each emphasized control or result, retain an uncropped full-viewport frame before the highlight and another full-viewport frame with the highlight; use a restrained overlay that does not hide the surrounding navigation or state.

Use believable, internally consistent synthetic records created through an authorized fixture path. Keep them clearly synthetic and free of real personal, customer, or regulated data. Capture the starting role, home screen, app revision, record identifiers, route, visible actions, resulting state, and durable readback. A success toast alone does not prove persistence; reopen the same record through the normal UI and confirm the changed value.

For every role in scope, start a separate session/profile at that role's real home and teach only actions the role is permitted to take. Include relevant expected restrictions. Before calling the walkthrough reproducible, give the exact instructions and synthetic setup to an independent fresh role session with no coaching. Have that operator follow from the home screen, note every ambiguity or missing visible step, fix the walkthrough, and replay the affected path. Preserve a compact evidence map linking each instruction to its captured screen/action and verified result. If an independent replay or a required role is unavailable, report the gap instead of claiming the walkthrough is independently verified.

Observe the page, identify the role, origin and destination, and use named controls for navigation, filtering, form filling, uploads and downloads. Use bsk step for a single decided action, bsk plan for steps known from one observation, and observe again when the next choice depends on new data. Check expectations before a consequential click. For login or human takeover, ask in the conversation first. Window-raising commands, interactive recording, and borrowing user tabs require an explicit handoff for that task. If a workflow requires a native popup and guarantees against foreground activation, use an isolated headless browser.

For inbox and calendar administration, scheduling, account portals and document submissions, identify the account and intended recipients or destination first. Compare the visible signed-in account and destination against the requested identity immediately before submitting. If either differs, stop before entering or submitting data. Prepare the requested change, inspect the real compose or confirmation screen and act within the user's authorization. Verify the sent item, reopened record or downloaded file. If a response is ambiguous, inspect the business record before retrying. Stop only your own session.
