# Technical Explainer

## Rules

1. Name the concept in one sentence the viewer can reuse at work.
2. Show before tell — point to a visual in `scene-plan`.
3. Avoid jargon stacks; define once, then use.
4. Tie explanation to a receipt (what broke / what the PR actually changed).

## Output

- `episode.yaml` → `technical_takeaway`
- Teaching narration blocks in `script.md`
- Companion doc bullets under `07-companions` or `episodes/*/companion.md`
