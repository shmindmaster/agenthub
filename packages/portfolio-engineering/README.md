# Portfolio engineering

Version 1.0.2. The `portfolio-engineering` capability owns the explicit portfolio
inventory, local evidence contracts, dependency preparation and tested structural
checks. Product repositories retain their own architecture, tracker and test/build
commands. This package does not merge, deploy, change mail settings or send mail.

## Inventory and evidence

```powershell
node packages/portfolio-engineering/scripts/portfolio.mjs inventory
node packages/portfolio-engineering/scripts/portfolio.mjs report "$env:LOCALAPPDATA/AgentHub/portfolio-engineering/baseline"
node --test packages/portfolio-engineering/scripts/*.test.mjs
```

`portfolio.json` is the explicit task roster and lifecycle overlay, not a second
repository knowledge standard. `registry/repo-standard.json` remains authoritative
for that standard. Inventory verifies Git root/remote/common-directory identity,
enumerates tracked manifests and records index freshness. Private evidence and
unlisted repositories are refused. Missing checkouts/tools are blocked.

`status: passed` on an inventory row means collection succeeded. It says nothing
about product safety. Product checks retain `not-run`, `blocked`, `failed`,
`passed`, or `not-applicable` dispositions with supporting evidence. Record
findings using `schemaVersion: 1`, `recordType: finding`, `repo`, full `head`,
`severity`, `workflow`, `evidence`, `correction`, `validation`, `disposition` and
`status`. Execution records use `recordType: execution`, `repo`, full `head`,
`branch`, `commands` (command, exitCode, finishedAt), `review`, `rollback`,
`stage: local` and `status`. `validate-record` rejects stale SHA/branch and dirty
worktrees: an uncommitted diff must be reviewed separately and cannot be certified
by HEAD-only evidence. Generated and operational reports belong outside Git.

## Dependencies

Pin preparation tooling to Renovate 44.69.13. Set `PORTFOLIO_RENOVATE_REPOS` to
an exact comma-separated selection from the roster's `renovate-candidate` rows.
Set `RENOVATE_CONFIG_FILE` to the absolute path of `renovate/config.cjs`. Configuration
always starts as a full dry-run; credentials come from the invoking environment.
Global autodiscovery is disabled. Existing GitPin/CrewScore Dependabot ownership
is preserved. Do not schedule this runner or remove dry-run without approval.

Use `scripts/Invoke-PortfolioRenovate.ps1 -Repositories shmindmaster/mahumtech`
with an existing authorized `RENOVATE_TOKEN` injected into the child process.
The wrapper accepts no arbitrary Renovate flags and forces a full dry-run and
the exact selected allowlist. It does not acquire or persist credentials.

Repository presets belong in `renovate/default.json`; global options live only
in `renovate/config.cjs`. Before activation validate against Renovate's schema,
inspect extracted npm/Poetry/PEP621/uv dependencies and proposed lockfile changes,
then run each repository's frozen install and native checks. Preserve deliberate
pins and framework constraints. Nothing here mandates one package manager.

## Structural checks and pattern propagation

Pin ast-grep CLI 0.45.3. Run `ast-grep test --config rules/sgconfig.yml` from this
package. The first rule finds process-wide TLS verification disablement in
TypeScript. Run scans in report-only mode until findings are reviewed. It has no
autofix: choosing the correct certificate configuration requires context.

Each future codemod must have positive, negative and second-run/idempotence
fixtures plus a pilot application test before propagation. Do not use an AST
match as evidence of authorization correctness. Native product checks and DO
build contracts remain authoritative; do not create blanket Actions workflows.

## Measurement

Keep RepoWise for derived intelligence, Git/ripgrep for exact current source and
GitPin for commit-pinned evidence. Evaluate the installed Understand CLI before
adding Lizard. Report metric producer/version, source SHA, language, exclusions,
coverage and measured timings; never average incompatible analyzer scores.
Defer Zoekt, Sourcegraph, OpenRewrite, CodeScene and SonarQube until a demonstrated
gap and separate decision justify them. No cloud code upload is authorized.

Use `repowise update <absolute-repo-path> --no-workspace --index-only --no-agents`
for scoped maintenance after confirming checkout ownership and cleanliness.
Before updating, record checkout status and the existing `.claude/` and
`.vscode/` integration files. The installed update path can generate
`.claude/CLAUDE.md`, `.vscode/mcp.json` and `.vscode/extensions.json` even with
`--no-agents` and `REPOWISE_SKIP_EDITOR_SETUP=1`; the latter was tested and did
not suppress these writes. Do not treat either setting as an integration guard.
Afterward, compare the exact files with the baseline and remove only files
proven to have been newly generated by that invocation. Preserve pre-existing
files and report any modifications separately. Do not adopt per-repository MCP
registrations as a replacement for AgentHub's shared capability owner.
RepoWise 0.48.0's workspace `--repo` route also runs cross-repository analysis;
the explicit single-repository route avoids that extra scope. New local indexes
use `init --no-workspace --mode fast --no-prose --no-agents --no-codex
--no-editor-setup --no-distill-hook --no-save-key --no-onboarding`. Keep generated
indexes ignored locally; uncommitted source requires separate diff evidence.

## Mailbox preparation

`scripts/Export-MailboxBaseline.ps1 -Mailboxes <explicit-addresses>` collects
recipient identity, mailbox properties, permissions, forwarding rules and
organization policy through read-only Exchange cmdlets. It requires exactly one
authenticated Exchange session and writes only to the separate local operational
directory. Blocked sections stay blocked; they do not establish missing mailboxes.
No permission, forwarding, provisioning or mail-send command is included.
