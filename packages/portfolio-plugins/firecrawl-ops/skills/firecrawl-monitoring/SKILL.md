# Firecrawl Monitoring

List existing monitors before creating, changing, running, or deleting any. Confirm URL scope, schedule, retention, notification path, and human review owner. Use monitor checks and change-tracking output to compare prior/current signals. Summarize changes with source URL, fetched time, prior/current signal, severity, and recommended action.

Use narrow monitors for specific pages and bounded crawl status for ingestion jobs. Never automate high-impact changes from legal, healthcare, finance, customer, or dispute sources; queue review instead.

Read `../../references/security-and-compliance.md` before handling sensitive sources.
